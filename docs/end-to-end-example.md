# End-to-end example: employer checkup

SPDX-License-Identifier: CC-BY-4.0

**Synthetic walkthrough, not an executed booking or real patient case.** Provider A/B are invented labels. Prices, slots and medical instructions are intentionally not fabricated.

1. **Intent.** User: “I need a health checkup in Japan.” Agent asks whether it is for work/school, an invitation or personal screening. User says a new employer needs a Japanese certificate and supplies a redacted form. The agent inspects it locally if possible rather than asking the user to transcribe everything. Without document tools it offers guided reading; cloud OCR would require separate transmission consent.
2. **Requirements.** The agent extracts the original test labels, issuer, certificate format and deadline with page references, marks uncertain OCR and asks only about the unclear field. It separates 雇入時 from 定期健康診断. It verifies the legal baseline and employer additions for the intended exam date; a notice applying April 2027 is not silently applied to an earlier exam. Conflicting evidence pauses recommendation.
3. **Constraints.** Now station/area, available days, travel tolerance and language matter. The user needs English communication and results before the employer deadline. No exact address, date of birth, insurance identifier or medical history is needed for this discovery step.
4. **Shortlist.** A live search would compare the required test matrix, exact branch, total quoted fees, certificate handling and delivery dates. Provider A has an English page but support is unknown. Provider B has appointment-specific confirmation of booking/exam language and employer-form handling. This example assumes that confirmation is obtained with consent; it does not assert that either provider exists. Missing mandatory items or turnaround evidence prevents a suitability claim. The user chooses only after the unresolved differences are explained.
5. **Booking and takeover.** The agent describes Japanese fields without rewriting the site's DOM. `受診票` is explained as the health-check form to complete/bring according to that provider. `保険証番号` is not substituted with My Number. Before entering sensitive fields, the user reviews what goes to the provider and why. When an OTP or bot checkpoint appears, the user takes over; the agent provides a side-by-side procedural guide and never requests the OTP in chat. Without automation the same guide supports manual booking.
6. **Confirmation.** Before final submission, review branch/package, date/time/timezone, price, cancellation terms and exact data recipient/payload. Approval is one-action-specific. The agent reads the actual receipt afterward; if absent, it says “unconfirmed” and checks status rather than submitting again. No claim of booking merely because a button was clicked.
7. **Preparation.** The user's Japanese confirmation supplies actual arrival, questionnaire, documents, sample kit and food/water instructions. The agent translates those instructions with exceptions intact and asks the provider to resolve medication or contradictory instructions. It does not supply a generic fasting interval. Reminders remain a user-owned checklist unless a scheduling tool actually creates them with separate consent.
8. **Attendance/payment.** The checklist covers the correct branch, required documents, accessibility/travel, payment method and receipt needed for employer reimbursement. A changed appointment or cancellation needs a new review and confirmation.
9. **Results and submission.** The agent checks result delivery and certificate format against the deadline. If `要精密検査` appears, it explains that the provider requests further examination, without diagnosing or declaring job fitness; it helps arrange clarification/follow-up preserving the stated urgency. Employer paperwork is a separate process. Sending even a subset of results requires recipient/minimum-page review and consent.
10. **Closure.** Record in session: results received, certificate submitted and acknowledged, reimbursement pending or resolved, clinical follow-up arranged or pending. Offer an optional minimal checkpoint outside Git with no dates, names or medical details; otherwise save nothing. Only now offer a voluntary public-source refresh using the user's own quota, never their case data.

This lifecycle is the intended agent behavior. The offline tests validate selected decision gates on synthetic facts, not every conversational turn or actual website interaction.
